💡 The Core Idea

A self-evolving agentic loop where an LLM iteratively rewrites its output guided solely by external quality scores — no access to model internals needed.

Step 1
LLM Generates
textt
→
Step 2
Oracle Scores
score = f(textt)
→
Step 3
Inject Feedback
score → prompt
→
Step 4
LLM Rewrites
textt+1
↩
repeat until all oracles pass
✓   Loop terminates when score crosses the target threshold — or max iterations reached
Key Insight

The oracle only needs to return a score. It does not need to be differentiable, open-source, or even documented internally. This makes the loop applicable to grammar checkers, readability formulas, factuality verifiers, and AI detectors — all with the same code, zero modification.

⚡ Why Prompt-Only? The Generalization Argument

Existing gradient-based and token-level methods are fundamentally tethered to a single oracle type. Here is why.

🔬 Connection to Automated Scientific Discovery

This is an instance of a paradigm shift happening across AI: using agentic loops with external feedback signals when gradient flow is unavailable.

AI Scientist · Sakana AI (2024)
Generate paper → evaluate (reviewer score, experiments) → refine. Evaluator is non-differentiable.
FunSearch · DeepMind (2023)
Generate program → run fitness function → score feeds back to LLM. No gradient through evaluator.
Our Work · Text Quality
Generate text → score quality oracle(s) → inject score as prompt feedback → rewrite.
The Pattern

When the evaluation function is non-differentiable — which is the norm, not the exception, in real-world settings — prompt-based feedback loops are the architecturally natural choice. This work applies that paradigm to text quality optimization and is the first to study it systematically across multiple oracle types.

❓ Research Questions

  • RQ1 Does a prompt-only agentic loop successfully reduce AI detection scores without gradient access or training?
  • RQ2 What are the convergence dynamics — how many iterations are needed, does quality degrade as scores improve?
  • RQ3 Does the same unmodified loop successfully optimize text against non-detection oracles (readability, grammar, toxicity)?
  • RQ4 Can the loop simultaneously satisfy multiple quality constraints using a combined feedback signal?
  • RQ5 Does loop performance generalize across text domains (news, essays, Wikipedia, medical)?
  • RQ6 What is the performance cost of oracle-agnosticism vs. gradient methods on the detection task specifically?

🎯 Result-Agnostic Design

The study is designed to be publishable regardless of outcome direction. The contribution is the systematic study itself.

If Results Are Positive
Prompt-only loops are surprisingly competitive
We don't need gradients for this class of problem. Loops match or approach gradient methods and uniquely generalize to non-differentiable oracles.
If Results Are Negative
We characterize the "prompt ceiling"
We identify the fundamental limit of prompt-only optimization and specify which oracle types require gradient methods — a principled guide for practitioners.
If Results Are Mixed
A taxonomy of oracle amenability
Some oracles respond well to natural-language feedback; others don't. We build a framework mapping oracle types to their amenability — itself a novel contribution.
Unconditional contributions regardless of any outcome: (1) formal framework definition, (2) open-source implementation, (3) convergence characterization, (4) comparison with gradient baselines.

💻 What the Loop Looks Like in Practice

All LLM calls use the Claude CLI — no API key setup, no model weights, no GPU required for the core loop.

# The loop calls the oracle, builds a prompt, and calls Claude CLI # Same 3 lines regardless of oracle type for iteration in range(max_iterations): result = oracle.score(current_text) # any oracle prompt = build_prompt(text, result, iteration) # inject score as text current_text = claude_cli(prompt) # claude -p "..." if result.passed: break # threshold crossed

The oracle is a black box that returns a score. Swap DetectionOracle for ReadabilityOracle or GrammarOracle — the loop code does not change.
